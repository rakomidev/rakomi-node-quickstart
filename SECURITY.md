# Security policy — Rakomi examples

The files in this repository are **example applications** that show how to build with Rakomi. They are
teaching artifacts: they consume the public Rakomi SDK and never re-implement a security primitive.

## Reporting a vulnerability

Please do **not** open a public issue for a security report.

- **Email:** security@rakomi.com
- **Canonical security policy:** <https://github.com/rakomidev/rakomi-js/blob/main/SECURITY.md>
- **Private vulnerability reporting:** <https://github.com/rakomidev/rakomi-js/security/advisories/new>

The canonical policy linked above is the single source of truth for supported versions, response
targets, and coordinated-disclosure terms. This file is a **thin, example-scoped pointer** to it —
it deliberately does not restate those terms here.

## Scope

This pointer covers the **example code** in this repository. A vulnerability in the Rakomi SDK or
platform itself is covered by the canonical policy linked above, not by this file.

> This is a GitHub-style `SECURITY.md` pointer, not a `.well-known/security.txt` web endpoint. The
> links above are **absolute** on purpose: each example lives in its own standalone repository,
> where a relative link to a parent policy would not resolve.
